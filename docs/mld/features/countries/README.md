# MLD — Countries

Source MCD: [docs/mcd/features/countries](../../../mcd/features/countries/README.md).

## MLD brut

The **MLD brut** is the relational schema obtained by applying the Merise transformation rules to the countries MCD, before any adaptation.

Natural identifiers stay the primary keys. A subregion name is unique across all subregions, so `subregion_name` alone identifies a subregion.

| Relation       | Primary key      | Foreign key                                          |
| -------------- | ---------------- | ---------------------------------------------------- |
| `t_regions`    | `region_name`    | —                                                    |
| `t_subregions` | `subregion_name` | `region_name` → `t_regions` (`region_name`)          |
| `t_countries`  | `iso_code_2`     | `subregion_name` → `t_subregions` (`subregion_name`) |

`t_countries` does not carry `region_name`: the country’s region is the region of its subregion (business rule 05). `ON UPDATE CASCADE` propagates a rename of a region or a subregion.

Business constraints already present on the brut schema:

| Constraint                   | Rule |
| ---------------------------- | ---- |
| `UNIQUE (country_name)`      | 07   |
| `UNIQUE (flag_url)`          | 09   |
| `iso_code_2 ~ '^[A-Z]{2}$'`  | 08   |
| `area_km > 0`                | 10   |
| `population >= 0`            | 11   |
| `subregion_name` primary key | 12   |

## Adaptation — artificial identifiers

**Choice:** every table receives an artificial primary key. The key has no business meaning and is generated by the database.

| Table          | Artificial primary key                              | Former primary key, kept as a uniqueness constraint |
| -------------- | --------------------------------------------------- | --------------------------------------------------- |
| `t_regions`    | `region_id INTEGER GENERATED ALWAYS AS IDENTITY`    | `UNIQUE (region_name)`                              |
| `t_subregions` | `subregion_id INTEGER GENERATED ALWAYS AS IDENTITY` | `UNIQUE (subregion_name)`                           |
| `t_countries`  | `country_id INTEGER GENERATED ALWAYS AS IDENTITY`   | `UNIQUE (iso_code_2)`                               |

`GENERATED ALWAYS AS IDENTITY` (PostgreSQL 18) is used instead of `SERIAL`: the identifier is a standard identity column, and an insert cannot override it by accident.

### What changes

1. **References no longer depend on business values.** Renaming a region, a subregion or an ISO code updates a single row. Foreign keys point at an integer that is not updated, so `ON UPDATE CASCADE` is removed.
2. **`t_subregions` references `t_regions` through `region_id` only.**
3. **`t_countries` references `t_subregions` through `subregion_id`.** In the brut schema the same link is `subregion_name`. The country’s region stays that of its subregion (business rule 05).
4. **`ON DELETE RESTRICT` stays.** A region that still has subregions, or a subregion that still has countries, cannot be deleted.
5. **Business uniqueness and checks are unchanged:** ISO format, `area_km > 0`, `population >= 0`, unique country name, unique flag URL, unique ISO code, unique subregion name.

### What the schema still does not enforce

The cardinalities “at least one” (a region contains at least one subregion, a subregion groups at least one country) are not expressed by a foreign key. The brut schema had the same limit.

### Adapted schema

Script: `database/sql/features/01_countries/01_ddl_create_tables.sql`.

| Relation       | Columns                                                                                                                                                        |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `t_regions`    | `region_id` PK, `region_name` UNIQUE NOT NULL                                                                                                                  |
| `t_subregions` | `subregion_id` PK, `region_id` FK NOT NULL, `subregion_name` UNIQUE NOT NULL                                                                                   |
| `t_countries`  | `country_id` PK, `iso_code_2` UNIQUE NOT NULL, `country_name` UNIQUE NOT NULL, `flag_url` UNIQUE NOT NULL, `area_km`, `population`, `subregion_id` FK NOT NULL |

```text
t_regions (region_id PK, region_name)
    ▲
    │ region_id
t_subregions (subregion_id PK, region_id FK, subregion_name)
    ▲
    │ subregion_id
t_countries (country_id PK, iso_code_2, country_name, flag_url, area_km, population, subregion_id FK)
```
